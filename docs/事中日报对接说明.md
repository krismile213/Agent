# 事中日报 对接说明

> 对象：`work-main/data/<品类>/<品类>/reports/事中日报_<YYYYMMDD>.xlsx`
> 性质：**数据后台系统（平台）的产物**，与 agent 的「晨检/午后简报」（钉钉推送）是**两套东西**，互不覆盖。
> 本文说明它的位置 / 结构 / agent 侧怎么读 / 建议的接入方式。核对时间：2026-10-15。

## 1. 定位与分工

| | 晨检 / 午后简报 | 事中日报 |
|---|---|---|
| 谁产出 | agent `daily_brief.py`（计划任务 09:00 / 14:20） | 数据后台系统（平台，每日 09:00 / 14:10 生成） |
| 形态 | `briefs/<YYYY-MM>/<日期>.md`（晨检 + 午后更新同一份，按月归档）+ 钉钉推送 | `data/<品类>/<品类>/reports/事中日报_<YYYYMMDD>.xlsx` |
| 数据源 | work-main 的 `Part*.xlsx` 副本 +（可选）平台后端 | 平台自身的在研 / 超期 / 风险计算 |
| 消费方 | 钉钉群 | 平台前端「事中日报」页；agent 可按需读取 |

**要点：事中日报不属于简报的一部分**，不要把它塞进晨 / 午报的六节结构里。要推它，另起一条链路。

## 2. 文件结构（6 个 sheet）

路径示例：`work-main/data/手机膜/手机膜/reports/事中日报_20261015.xlsx`
（同目录另有 `复盘报告_<YYYYMMDD>.xlsx`，属事后评估线，不在本文范围）

⚠️ 读表注意：**每个 sheet 第 1 行是标题、第 2 行空、第 3 行才是表头**（`header=2` 或按名定位）。

### ① 在研SKU状态总表
`SKU | 型号 | 状态 | 当前停留环节 | 部门 | 已停留(天) | 目标(天) | 距超时(天) | 预警段数 | 多轮提交 | 核心原因 | 责任人 | 人工登记`

> 末列「人工登记」（2026-10-15 新增）是**跟着日期走**的在研备注（如「暂时不弄了」）。
> 真源在生成器之外的 `资产文件\事中日报人工登记.xlsx`（子表 `人工登记`，列 `SKU｜备注｜更新日期`），
> 由平台侧 `app/sku_note.py` 每次生成时读入 —— 因为日报每天整体重新生成、幂等覆盖，
> 手填在表里会被冲掉。注意它与「豁免备查」里的**人工登记（免催办）**是两件事：
> 那个会把 SKU **移出追踪**，这个只影响展示。引用这条备注判断"要不要催办"时，
> 优先级高于系统算出的超期天数。

### ② 超期明细
说明行："进行中超期段（终点未完成，elapsed > 目标天）"
`SKU | 部门 | 环节 | 已进行(天) | 目标(天) | 超期(天) | 责任人`

### ③ 风险预警
说明行："即将超期预警（已进行 > 目标 × 预警系数，未到目标）"
`SKU | 部门 | 环节 | 已进行(天) | 目标(天) | 预警线(天) | 责任人`

### ④ 在研SKU甘特图
宽表（每格 = 1 天），按 SKU 分块；每块首行形如
`G604 · Xiaomi Poco X8 5G    状态: 进行中    当前停留: 取数→签样    距超时: 剩7天`，
下面是分段条形。颜色：产品部(蓝) / 运营部(绿) / 后勤部(橙) / 运输(紫) / 4国(金) / 留空(灰)。

### ⑤ 异常上报清单
说明行："异常上报（当日新超期 + 持续超期累计）"
`类型 | SKU | 部门 | 环节 | 超期(天) | 已进行(天) | 责任人`

### ⑥ 豁免备查
说明行："已移出追踪的 SKU（人工登记 / 换号 / 末端终止作废 / 运输闭环）"
`SKU | 型号 | 豁免类型 | 原因`

## 3. Agent 侧读取途径（两条）

**途径 A — 平台后端（推荐用于交互问答）**

| 工具 | 作用 | 前提 |
|---|---|---|
| `platform_daily_report` | 列出平台已生成的事中日报（按日期，只读） | 平台后端在线 |
| `platform_inflight_overview` | 在研 SKU 清单 + KPI（当前停留 / 距超时） | 同上 |
| `platform_inflight_alerts` | 当日新超期 / 持续超期 / 临近超期(85%) | 同上 |

- 前提：数据后台系统（平台 `start.py`）在跑，`config.json` 的 `platform_root` 指对；返回前自动脱敏。
- 优点：与平台页面**同源**，口径一致。

**途径 B — 直接读本地 xlsx**

- 文件就在 work-main 下；但 `read_file` 读不了 xlsx（二进制），得用 pandas。
- `run_python` 能读，却是**写级**工具 —— **无人值守的晨 / 午报注册表里会被摘除**，所以简报链路里用不了，只在交互模式可用。
- 若要在只读链路用，用**只读工具 `inflight_report`**（见 §4，2026-10-15 已实现）。

## 4. 只读工具 `inflight_report`（✅ 已实现，2026-10-15）

```
inflight_report(line="手机膜", date=None) -> str
  读 data/<line>/<line>/reports/事中日报_<date|最新>.xlsx
  返回结构化摘要: 在研状态总表(状态/当前停留/已停留/目标/距超时/预警段/核心原因/人工登记)
                  + 超期明细 + 风险预警 + 异常上报清单 + 豁免备查(SKU级)
  只读、纯 pandas、不依赖平台后端 → 可进无人值守注册表
```

落地位置：`plugins/workmain.py`（`register()` 内，与 `scan_sync_data`/`pipeline_alerts` 同族）；
单测 `scripts/test_inflight_report.py`（已接入 `scripts/run_all.py`）。

- `date` 缺省读最新一份；支持 `YYYYMMDD` 与 `YYYY-MM-DD` 两种写法；不存在则人话报错并附已有日期清单。
- `line` 枚举仅 `手机膜` / `手机壳`（顺带挡掉路径逃逸）。
- 表头按 row3 解析（row1 标题 / row2 空 / row3 表头），与 `reporting.py` 写入结构一致；旧版缺表时跳过该节而不报错。
- **末列「人工登记」会原样带出**（2026-10-15 起）：这是跨日期延续的在研备注，催办前必读的
  业务决策（如「暂时不弄了」→ 别再当卡点催办）；它的真源是生成器之外的
  `资产文件\事中日报人工登记.xlsx`，平台侧 `app/sku_note.py` 每次生成时读入。
- **甘特图 sheet 不做文本化**（227 列宽表，看图去平台页面）。

**脱敏口径（与平台 API 对齐，写死在测试里的红线）**

xlsx 的「责任人」列是真实姓名、「豁免备查 → 原因」含登记人姓名（如"林宇炫 2026-01-16 创建"），
而平台 `outbound_guard` 词典没有"责任人"这一条、平台 API 也从不返回该字段 —— 所以本工具
**只读所需列，不读 责任人 / 豁免原因**，自由文本（型号 / 核心原因 / 人工登记）过手机号掩码。
`scripts/test_inflight_report.py` 拿 xlsx 里的真名回来硬比对，泄漏即 FAIL。

- 交互问答：途径 A / B 都行。
- 定时推送：若要把事中日报纳入推送，用 `inflight_report` 另起一条链路（**不并入晨 / 午报**）。

## 5. 口径提醒（重要）

- 事中日报的「当前停留环节 / 已停留 / 目标」是**平台侧**口径（segment 名，如"素材加工→广告"）；
  agent 的 `pipeline_alerts` 用 **Part 编号**（如 Part8）+ 段级近似口径。**两者数字可能不一致**，
  引用时必须注明来源。
- 事中日报每日 **09:00** 生成；当天上游数据未同步时，其数字会停在上一场。
