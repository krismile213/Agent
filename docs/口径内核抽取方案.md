## 3. `rules/` 包设计

### 3.1 定位

- **纯计算，零 IO**：不读 xlsx、不读 DB、不连 `:8000`、不 import pandas。
- **数据与规则分离**：包只导出「结构 + 函数」，值由调用方注入（快照 JSON / 测试 fixture）。
- **不含 PII**：后端 `SEGS` 每段带责任人（李杰华/周奕奕/郭晋盈/林宇炫/梁子锋/林惠欢）。
  Agent 是数据上云最后一跳，**责任人绝不能进包里**。抽取时只取 `(部门, 环节, 起点, 终点, 目标, 是否留空)`，
  人名留在后端；包里加一条单测断言"序列化结果不含人名"。

### 3.2 目录

```
rules/
  __init__.py          # 对外只导出这几个名字，其余私有
  stages.py            # PART_STAGE（Part→环节名）+ STAGE_ALIAS（"渠道仓到货"→Part8）
  segments.py          # SEG_DEFS：段定义（起终点/部门/目标/是否留空），不达人名
  mapping.py           # SEG_TO_PART：段→Part 的显式折算表（含"不可折算"的显式声明）
  targets.py           # resolve_targets(snapshot|None) → Targets，含加载/校验/降级
  rules.py             # 判定函数：stage_of / pending_flags / sign_overdue / generic_material
  constants.py         # STALE_CAP_DAYS / NEW_SKU_WINDOW_DAYS / GENERIC_SAVE_DAYS / FULL_ROUTE
  version.py           # SCHEMA=1，与快照 schema 对齐
```

### 3.3 对外 API（最小面）

```python
load_targets(path=None) -> Targets      # 读快照；缺失/损坏/类型不对 → 返回代码默认 + .warnings
part_target(t, part) -> int | None      # Part 级目标；None = 该 Part 无段级定义（**不是 0**）
seg_target(t, seg) -> int | None
PART_STAGE: dict[str, str]
STAGE_LABEL(part) -> str                # "Part8(渠道仓到货检查)"
stage_of(docs, t, sku, today) -> Stage  # 现环节 + 已持续 + 是否超目标
pending_flags(docs, t, sku, today) -> list[str]
is_generic_material(part6_docs) -> (bool, str)  # 判据 + 依据
```

### 3.4 三条硬性设计决定

1. **`None` ≠ `0`**。`available=False`（留空段）必须映射成 `None`，调用方要么跳过判定、要么标注"无目标"。
   现在的 `targets.get(part, 1)` 把"没配"当成"1 天"—— 一个漏配的环节会被当成极严格的目标去催，比不催更糟。
2. **折算表必须显式且带"不可折算"声明**。`mapping.py` 里 Part8/Part9/壳 Part1 写成
   `None, reason="无段级起点终点，目标来源=transport_mode"`，让调用方必须显式处理，不能默默取默认。
3. **值与来源一起返回**。`Targets.source` = `"snapshot@2026-11-06#1"` / `"xlsx(legacy)"` / `"code-default"`，
   工具输出里带一行「口径来源」，出问题时一眼定位用的是哪份。

## 6. 写能力三样：怎么落

> 顺序建议：**审计 → 幂等 → 隔离**。前两个便宜且立刻有用；隔离要等真有第二个使用方再做，
> 现在做等于给一个租户造多租户系统。

### 6.1 审计（先做，约 1 天）

- 新表 `audit(id, ts, tenant, session_id, tool, args_hash, args_preview, result_hash,
  level, approved_by, outcome, latency_ms)`，**append-only**：
  代码层不提供 update/delete，另加 SQLite 触发器 `BEFORE UPDATE/DELETE ... RAISE(ABORT)`。
- 落点：`Registry.execute()` 一处（不是每个工具里），保证"绕过工具"不可能。
- `args_preview` 走 `_plat_sanitize` 同一套敏感键剔除，**不落明文**。
- 外发类（`dingtalk_send`）额外记 `approved_by` + 预览文本 hash。
- 验收：跑一条 `write_file` → 表里一行、预览无敏感值、`DELETE` 报错。

### 6.2 幂等（约 1 天）

- `idempotency_key = sha256(tool_name + canonical_json(args))`，canonical = 键排序 + 去空白。
- `Registry.execute()`：写级工具先查 `audit` 表最近 N 分钟同 key 的成功记录 → 命中则**直接返回首次结果**，
  并在返回头加 `dedup:true`（模型能看见，避免它以为没执行）。
- 只对 `level in (write, external)` 生效，读工具不拦（读重复无害）。
- 验收：同一 `run_route_check` 连调两次 → 第二次秒回、产物 mtime 不变。

### 6.3 隔离（暂缓，触发条件写清楚）

- `tenant_id` 从 `auth.tokens[token] → tenant` 派生，贯穿：会话目录、`uploads/`、`agent.db` 行级过滤、
  工具白名单、`platform_root`。
- 沙箱根按 tenant 派生（`safe_path` 已集中，改一处）。
- **现在不做**：没有第二租户时，这套改动只增加出错面。触发条件 = 出现第二个真实部署。

## 7. `:8000` 降级要显式

现在的行为：`_plat_get` 失败 → 返回错误字符串 → 模型自己退回读 xlsx → **顺手写一句"数据来源：平台"**。
这是最坏的一种：数据是旧的，来源是假的。

### 改法（三态 + 一处收口）

```python
# plugins/workmain.py::_plat_get 返回 (obj, err) 保持兼容，另加 _plat_state() 记录最近一次探测结果
STATUS_OK        = "ok"
STATUS_DEGRADED  = "degraded"    # 平台不可用，本次结果来自本地副本
STATUS_UNAVAILABLE = "unavailable"  # 无本地副本，拒绝作答
```

1. **工具层统一横幅**（所有 `platform_*` 与依赖平台数据的 workmain 工具，在返回**第一行**插）：
   ```
   ⚠️ 数据源降级：平台后端(:8000)不可用，以下为本地副本(事中日报 / Part*.xlsx)，
   截至 2026-11-16 08:48，口径可能与平台页面有差 —— 转达时请原样保留本行。
   ```
2. **系统提示加一条硬规则**：出现「数据源降级」时，(a) 原样转达该行；(b) 禁止写"数据来源：平台"；
   (c) 涉及金额/时效结论时必须加"（降级数据）"。
3. **`daily_brief` 侧**：① 开头加一句"数据源：平台/本地降级"，且**降级时不允许生成⑥行动建议**
   （旧数据催人 = 催错对象，比不催更糟）。
4. **探活**：`/api/health` 里带 `platform: ok|down` + 最近成功时间，Web UI 顶栏显示一个小圆点。

**验收**：`wm_plat_degrade` 用例（第 11 条）—— 关掉 :8000，断言首行是横幅、全文无"来源：平台"。
