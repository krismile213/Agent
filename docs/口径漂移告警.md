# 口径漂移告警

给"业务规则数字"装的 CI。代码有单测防回归，但口径数字散在规则快照 / 时效确认规则表 / 内置常量三处，改错没人知道，更阴的是**静默回退**（真源都在，来源却悄悄变成兜底）。本机制在每次发简报前体检，发现漂移就禁催 + ⑥ 段告警，把"悄悄用错数字"变成"当场暴露"。

## 三查

| 查 | 实现 | 抓什么 |
|---|---|---|
| 查一 值漂移 | `drift_check.check_values` | resolve 权威值偏离裁决基线 `CANONICAL_TARGETS`（某真源被偷改） |
| 查二 来源回退 | `drift_check.check_sources` | snapshot 可用但 Part 来源退成 xlsx/default（漏导出 / ImportError 被吞） |
| 查三 hash 漂移 | `drift_check.check_hashes` | 快照/xlsx 文件 hash 相对基线变化（源被改过，提示复核） |

**为什么查二不能省**：兜底值 `PART_TARGET_FALLBACK.Part1` 也写成了 13（与真源同值），所以静默回退后**数值不变**，光比数值抓不到，只有来源会从 `snapshot` 变成 `default`。2026-11-16 `rules/__init__.py` 漏导出就属于这类——直调单测全绿，接入层却回退。

## 已知豁免（防误报）

- **Part1 膜 13(快照) vs 75(xlsx)**：用户 2026-11-16 拍板收紧到 13，xlsx 是旧值。查一比的是 resolve 输出(13) vs 裁决基线(13)，天然避开，不会天天误报。
- **手机壳 Part1=75**：不折算、待业务校准，有自己的基线；且不纳入来源检查（壳无「取数」段）。

## 数据流

```
rules/drift_check.py   纯函数（零 IO，吃 resolved/sources/hashes，不读文件）
        ↑ 喂数据
drift_probe.py         IO 探针：读快照+xlsx、算 sha256、读写 drift_baseline.json
        ↑ 收尾调用
daily_brief.finish()   enforce_drift_guard：有 ⛔ 横幅则把 ⑥ 换成"暂不催办"
```

- hash 基线 `drift_baseline.json`（gitignore，可重建）按品类分键；**首次运行只建基线不报**；只在无漂移时滚动，漂移时保留旧基线持续提醒。
- 失败静默降级：探针任何异常都返回 OK，只在日志留痕，绝不阻断简报生成。
- 与新鲜度守卫的关系：两者都是 finish() 最后一道关卡；同时命中时**新鲜度优先**（它更贴近"数据在不在"的前提），避免 ⑥ 出现两条冲突提示。

## 手动体检

```bash
python drift_probe.py          # 膜+壳各跑一次，打印 state/findings/banner
python scripts/test_drift_check.py   # 26 项单测
```

## 合法改口径时

改了真源（快照/规则表）后，必须**同步更新 `rules/drift_check.py::CANONICAL_TARGETS`**，否则会被判值漂移——这是强制评审的意图，不是 bug。

## 边界

- 只体检"环节目标天数"一类口径；SIGN_TARGET_* / STALE_CAP_DAYS 等写死常量尚未纳入（在 `probe_rule_drift.py` 的 HARDCODED 清单里，后续可搬）。
- 不自动修真源、不改 xlsx；只告警 + 禁催，处置仍靠人。
