# 钉钉定时简报手动补跑操作手册

**适用场景**：定时任务每天自动运行（数据同步 09:00 / 14:30，简报推送 09:30 / 14:45）。如果表单在定时同步**之后**才有更新——比如 14:40 才更新，错过了 14:30 那轮同步——群里的简报就缺这部分数据。按本手册手动补跑一次，即可让群里收到包含最新数据的简报。

**核心原则只有一条：先同步，后简报，顺序不能反。** 简报的数字全部来自同步落地的数据文件，不同步就直接跑简报，推出去的还是旧数据。

## 一、完整补跑流程（共 4 步，约 10 分钟）

### 第 1 步：手动触发数据同步

在 **PowerShell** 窗口中执行：

```powershell
Start-ScheduledTask -TaskName DingTalkApprovalSync
```

也可以用图形界面：按 `Win + R` 输入 `taskschd.msc` 回车，在"任务计划程序库"中找到 `DingTalkApprovalSync`，右键选择"运行"。

### 第 2 步：等待同步真正完成（约 7~8 分钟）

**注意：任务状态很快显示"就绪"不等于完成**——启动脚本会把实际工作转到后台，状态提前变回"就绪"。用下面任一方法判断真正完成：

| 判断方法 | 具体操作 | 完成标志 |
|---|---|---|
| 看同步日志 | 打开 `D:\Desktop\work-main\dingtalk\logs\` 下当天的 `sync_日期.log`，拉到最末尾 | 出现"体检完成"字样 |
| 看数据文件 | 打开 `D:\Desktop\work-main\data\手机膜\手机膜\` 文件夹 | 9 个 `Part*.xlsx` 文件的修改时间刷新为刚才的时间 |

### 第 3 步：跑简报并推送到钉钉群

双击运行：

```
C:\Users\dell\Desktop\Agent\run_brief.bat
```

约 1~2 分钟跑完，窗口出现 **"推送成功: 已发送"** 即表示群里已收到。中午 12 点前生成的是晨检版 `briefs\日期.md`，12 点后是午后版 `briefs\日期_pm.md`。

### 第 4 步：确认结果

打开群里刚收到的简报，核对第一节的 **"数据截至"** 时间：应是最近几分钟内，说明补跑成功、数据是新的。

## 二、只重跑简报（数据没变，只是想重推一次）

如果确认数据没有新变化，只是想重新推送一条简报，直接执行**第 3 步**即可，不用同步。注意群里会收到内容相同的一条新消息。

## 三、常见问题与注意事项

| 现象 | 原因 | 处理办法 |
|---|---|---|
| `Start-ScheduledTask` 命令报错或找不到 | 在 cmd 或"运行"框里直接执行了该命令 | 改在 **PowerShell** 窗口执行（开始菜单搜 PowerShell） |
| 同步等了很久文件还没刷新 | 同步正常需要 7~8 分钟；或确实失败了 | 到点再看一次；打开当日 `sync_日期.log` 末尾看有无报错，有则重做第 1 步 |
| 同步时 Excel/WPS 正开着某张 Part 表 | 被打开的旧文件删不掉，目录里残留新旧两份 | **不会算错数**——系统只认每个环节最新一份文件。关掉 Excel 后，下一轮同步会自动清掉残留 |
| 简报跑了一分多钟还没结束 | 免费模型偶尔限流（429），程序会自动重试或切换备用模型 | 多等 1~2 分钟即可，**不要中途关窗口** |
| 群里一天收到好几条简报 | 每次手动补跑都会新推一条 | 正常现象，以最新一条为准 |
| 简报里的日期或停滞天数明显不对 | 电脑时区不是北京时间 | 保持系统时区为 Asia/Shanghai（服务器部署详见 `docs/DEPLOY.md`） |

## 五、现有定时任务一览

| 任务名（任务计划程序） | 触发时间 | 作用 |
|---|---|---|
| `DingTalkApprovalSync` | 每天 09:00、14:30 | 从钉钉拉取审批数据，写入本地 Excel（9 个 Part 文件） |
| `AgentDailyBrief` | 每天 09:30 | 生成晨检简报并推送钉钉群 |
| `AgentDailyBriefPM` | 每天 14:45 | 生成午后简报并推送钉钉群 |

手动补跑的原理，就是按同样的顺序把"同步 → 简报"这套动作提前手动执行一遍，用到的任务和脚本与定时任务完全相同。
