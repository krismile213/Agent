# 单 SKU 流程复盘

## 什么时候用
用户问"G531 怎么样了 / 卡在哪 / 为什么慢了 / 下一步该催谁"，或者要一份可以拿去开会的单 SKU 说明。
一次只处理一个 SKU；多 SKU 对比用 `pipeline_alerts` + 简报流程，不要套本技能。

## 数据源与优先级
1. `platform_sku_route` —— **首选**。平台后端同源数据，各 Part 实际 vs 目标、卡点、三部门终节点。
2. `query_sku_route` —— 平台不可用时的降级（读 xlsx 副本）。用了必须在回答里注明"数据来自本地副本"。
3. `get_product_info` —— 补型号 / ASIN / 当前状态，用于把 SKU 编号翻译成人看得懂的名字。
4. `inflight_report` —— 要看"人工登记"备注时用。**备注优先级高于系统算出的超期天数**
   （业务上写"暂时不弄了"的单，不要催）。

## 口径纪律
- `caliber` 有两套：`action`（动作映射，默认）与 `system`（系统口径）。
  **两套结论不可混用**，回答里必须写明用的是哪套。
- Part 口径（pipeline_alerts / 平台）与 segment 口径（事中日报）不是一回事，
  混着报会让"卡在 Part3"和"卡在广告段"自相矛盾。
- 责任人字段平台侧已脱敏，不要尝试补人名；工具没给就不写。

## 输出结构（固定四段，非四段重写）
    Gxxx 型号一句话现状(卡在 PartN 环节名, 已进行 X 天 / 目标 Y 天, 超 Z 天)
    耗时拆解: 立项→首单 / 首单→上架 / 上架→到货, 哪段最快、哪段拖后腿
    卡点归因: 只写工具输出里能看到的（审批停在谁那 / 哪个节点没动 / 数据断供）
    下一步: 谁 + 做什么 + 什么时候前完成, 最多 2 条
超过 6 行就砍掉背景解释，保留数字和动作。

## 易错点
- 数据截至日早于今天时，先说明"数据未更新到今日"，再讲停滞天数 ——
  否则会把"没人审批"和"数据没同步"混为一谈。
- 停滞天数含数据断供期时，结论要打折，并显式写出断供天数。
- SKU 在「豁免备查」里就不要再报超期，豁免是业务主动移出追踪。
- 编号大小写、前后缀照抄工具输出（G531 不等于 531，也不要写成 "SKU 531"）。

## 验收
回答里每个数字都能指回某个工具的输出；四段齐全；下一步不超过 2 条且有对象和时间。
